# 페루 빙하 융해 · GLOF 위험 모니터

페루 안데스 빙하호의 **실시간 융해 조건**과 **빙하호 붕괴 홍수(GLOF, Glacial Lake Outburst Flood) 가능성**을
공개 기상·지진 데이터로 추적하는 대시보드입니다.

2025년 페루의 홍수 피해가 빙하 융해와 연결되어 보도되면서, "지금 빙하가 어떤 상태인지"와
"어느 호수가 위험한지"를 한 화면에서 보려고 만들었습니다.

> ⚠️ **이 대시보드는 공개 데이터로 만든 스크리닝 지표입니다.**
> INAIGEM · SENAMHI · INDECI 등 페루 당국의 공식 조기경보를 대체하지 않으며,
> 대피·통제 같은 실제 방재 판단의 근거로 사용해서는 안 됩니다.

---

## 무엇을 보여주나

| 화면 | 내용 |
|---|---|
| 요약 지표 | 최고 위험 지점, 전 지점 평균 0 °C 고도, 7일 융해 도일, 최근 30일 지진 |
| 지도 | 12개 모니터링 지점을 위험 등급 색으로 표시. 페루 전체 ↔ 산맥별 확대 |
| 지점 목록 | 위험도 · 융해 강도 · 하류 인구순 정렬, 최근 7일 기온 스파크라인 |
| 상세 분석 | 위험 요인 분해, 14일 기온 + 7일 예보, 0 °C 동결고도 vs 빙하 말단, 일별 강수(비/눈), 인근 지진, 장기 온난화 추세 |

모니터링 지점은 코르디예라 블랑카(팔카코차·513·파론 등 8곳), 와이타파야나, 코르디예라 비야노타,
그리고 융해 관측용 빙하 2곳(켈카야 빙모 · 코로푸나)입니다.

## 위험도 산정 방식

다섯 요인을 각각 0~1로 정규화해 가중 합산한 뒤, 지점별 정적 취약도를 곱해 **0~100**으로 환산합니다.

| 요인 | 가중치 | 근거 |
|---|---|---|
| 빙하 융해 | 30% | 빙하 말단 고도의 지난 7일 **양의 도일(PDD)**. 융해수 유입량의 대리 지표 |
| 0 °C 동결고도 | 20% | 동결고도가 빙하 말단보다 높을수록 융해면이 넓게 노출됨 |
| 강우 유입 | 25% | 최근 3일 + 향후 3일 강우. 호수 수위를 올리고 모레인 댐을 약화시킴 |
| 급격한 온난화 | 10% | 향후 3일 평균기온 − 지난 7일 평균 |
| 지진 활동 | 15% | 반경 250 km · 30일 내 지진을 규모/거리/경과일로 감쇠. 빙벽 붕락과 댐 붕괴의 방아쇠 |

정적 취약도(`baseHazard`)는 댐 형식, 호수 용적, 하류 노출 인구, 배수 터널 등 저감 시설 유무를 반영한
0~1 값이며 `0.5 + 0.5 × baseHazard` 배율로 곱해집니다. 같은 기상 조건이라도 하류에 12만 명이 사는
팔카코차가, 배수 터널로 수위를 낮춘 파론보다 높은 점수를 받습니다.

등급은 **관심(0~24) · 주의(25~49) · 경계(50~74) · 심각(75~100)** 네 단계입니다.

### 한계

- 호수 수위 · 모레인 댐 변위 · 빙하 두께를 **직접 관측하지 않습니다.** 기상·지진이라는 외부 조건만 봅니다.
- GLOF의 상당수는 기상과 무관한 빙벽·암반 붕락으로 촉발되며, 이 모델은 그 순간을 예측하지 못합니다.
- 가중치는 문헌의 정성적 인과관계를 반영한 값이지, 관측 사례로 보정(calibration)한 값이 아닙니다.
- 지점 제원(고도·용적·인구)은 공개 문헌 기반 근삿값이며 조사 시점에 따라 편차가 있습니다.

## 실행 방법

### 1. 로컬에서 바로 보기

ES 모듈을 쓰므로 `file://` 로는 열리지 않습니다. 정적 서버가 필요합니다.

```bash
python3 -m http.server 8000
# 또는
npx http-server -p 8000
```

브라우저에서 <http://localhost:8000> 을 엽니다. 브라우저가 Open-Meteo · USGS 를 직접 호출합니다.

### 2. Synology NAS 에 상시 구동 (권장)

브라우저만 쓰면 API가 주는 **최근 며칠 창(window)** 밖에 못 봅니다.
NAS에 수집기를 띄워 두면 이력이 쌓이고, 임계값을 넘을 때 알림도 받을 수 있습니다.

**Container Manager 로 (GUI)**

1. File Station 에서 `docker/peru-glacier` 폴더를 만들고 이 저장소를 올립니다.
2. Container Manager → **프로젝트** → **생성** → 경로를 그 폴더로 지정
3. 소스를 `docker-compose.yml` 로 두고 **다음 → 완료**
4. `http://<NAS주소>:8080` 접속

**SSH 로**

```bash
git clone <이 저장소> peru-glacier && cd peru-glacier
docker compose up -d
docker compose logs -f          # 수집 로그 확인
```

첫 수집이 끝나기 전에는 `/api/latest` 가 503 을 반환합니다. 1~2분이면 채워집니다.

배포 직후 파이프라인만 먼저 검증하고 싶다면 `DEMO=1` 로 한 번 띄워 보세요.
합성 데이터로 수집 → 이력 적재 → 알림까지 전 구간이 도는지 확인할 수 있습니다.
**확인이 끝나면 반드시 지우세요.** DEMO 모드의 수치는 실제 관측값이 아닙니다.

### 환경 변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` / `HOST` | `8080` / `0.0.0.0` | 수신 주소 |
| `DATA_DIR` | `./data` | `latest.json` 과 `history/*.jsonl` 이 쌓이는 경로 |
| `POLL_MINUTES` | `30` | 수집 주기 |
| `ALERT_WEBHOOK` | (없음) | 위험도 임계값 초과 시 POST 할 URL. Synology Chat · Slack · Discord · ntfy 호환 |
| `ALERT_THRESHOLD` | `50` | 알림 임계 점수. 지점당 6시간 쿨다운 |
| `DEMO` | (없음) | `1` 이면 합성 데이터 사용 (배포 점검 전용) |

### API

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/latest` | 마지막 수집 묶음 (전 지점 원시 기상 + 지진) |
| `GET /api/history?site=<id>&days=<n>` | 지점별 위험도 이력 (JSONL 을 파싱해 반환) |
| `GET /api/health` | 상태 · 마지막 수집 시각 · 경과 분 |
| `POST /api/collect` | 즉시 수집 트리거 |

대시보드는 같은 오리진에 `/api/latest` 가 있으면 **자동으로** 그쪽을 씁니다.
없으면 브라우저가 직접 API를 호출하고, 그것마저 실패하면 데모 모드로 내려가되
상단에 경고 배너를 띄웁니다. 세 경우 모두 화면 우상단 배지에 현재 데이터 출처가 표시됩니다.

## 구조

```
index.html                  대시보드 셸
assets/styles.css           다크 테마 스타일
assets/js/
  main.js                   부트스트랩 · 상태 관리 · 10분 자동 갱신
  sites.js                  모니터링 지점 정적 메타데이터
  risk.js                   위험도 산정 모델 (프론트엔드와 수집기가 공유)
  api.js                    데이터 수집 계층 (수집기 → 직접 호출 → 데모 폴백)
  charts.js                 의존성 없는 SVG 차트 (선/막대/추세/스파크라인)
  map.js                    타일 서버 없는 SVG 지도
  ui.js                     DOM 렌더링 컴포넌트
  demo.js                   결정적 합성 데이터 생성기
server/server.mjs           NAS 수집기 겸 정적 서버 (Node 20+, 의존성 없음)
Dockerfile, docker-compose.yml
```

**npm 의존성이 하나도 없습니다.** 차트와 지도를 직접 그려서 CDN·타일 서버 없이,
폐쇄망에서도 그대로 동작합니다. 위험도 판정은 `assets/js/risk.js` 한 곳에만 있고
브라우저와 수집기가 이를 그대로 임포트하므로 두 경로의 점수가 어긋나지 않습니다.
