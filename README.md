# 빙하 융해 모니터

전 세계 빙하가 **연대별로 얼마나 더워지고 녹고 있는지**, 그리고 페루 안데스 빙하호의
**실시간 붕괴 홍수(GLOF) 위험**을 함께 보는 대시보드입니다. 화면은 두 개의 탭으로 나뉩니다.

| 탭 | 무엇을 보나 | 시간 축 |
|---|---|---|
| **전 지구 빙하 변화** | 전 세계 19개 빙하 지역의 기온 상승과 융해 조건 | 1950년 ~ 현재, 연대별 |
| **페루 빙하호 경보** | 12개 빙하호의 GLOF 위험도 | 실시간 (과거 14일 + 예보 7일) |

> ⚠️ **이 대시보드는 공개 데이터로 만든 스크리닝 지표입니다.**
> INAIGEM · SENAMHI · INDECI 등 페루 당국의 공식 조기경보를 대체하지 않으며,
> 대피·통제 같은 실제 방재 판단의 근거로 사용해서는 안 됩니다.

## 1. 전 지구 빙하 변화

19개 [RGI(Randolph Glacier Inventory) 1차 지역](https://www.glims.org/RGI/) 각각의 대표 빙하 지점에서
**ERA5 재분석 일평균 기온(1950년~현재)** 을 받아 연·연대 단위로 집계합니다.

| 화면 | 내용 |
|---|---|
| 요약 지표 | 전 지구 빙하 면적, 19개 지역 평균 기온 상승, 융해 도일 증가 배율, 가장 빠르게 더워진 지역 |
| **지역 × 연대 히트맵** | 19개 지역 × 8개 연대(1950s~2020s)를 한 장에. 기온 상승 / 융해 도일 / 영상 일수로 전환 |
| 지역별 순위 | 기준기간 대비 상승폭 순 정렬, 빙하 면적 함께 표시 |
| 지역 상세 | 연평균 기온 시계열과 추세선, 연대별 융해 도일 막대, 연대 표 |

계산하는 세 가지 지표:

- **기온 상승** — 1951~1980년 평균 대비 각 연대의 기온 차이 (NASA GISTEMP 와 같은 기준기간)
- **융해 도일(PDD)** — 한 해 동안 0 °C를 넘은 기온을 모두 더한 값. 얼음을 녹이는 데 쓰인 에너지의 표준 대리 지표
- **영상 일수** — 한 해 중 하루 평균 기온이 0 °C를 넘은 날의 수

> **중요 — 이건 "융해 조건"이지 "녹은 양"이 아닙니다.**
> 빙하가 실제로 얼마나 얼음을 잃었는지(질량 수지)는 위성 고도 측정과 현장 관측으로만 알 수 있습니다.
> 그 수치는 공표된 연구값(예: 2000~2019년 평균 약 267 Gt/년, Hugonnet et al. 2021)을
> **정적 참고치**로 따로 표시하며, 대시보드가 계산한 값이 아님을 화면에 명시합니다.

### 이 방식의 한계

- 지역당 **한 지점**으로 대표합니다. 알래스카나 남극처럼 넓은 지역의 내부 편차는 담지 못합니다.
- 융해 도일은 강설량·부채(debris) 피복·빙하 역학을 반영하지 않습니다. 카라코람처럼 기온이 올라도
  강설 증가로 빙하가 유지되는 사례가 보고돼 있습니다.
- ERA5 는 재분석 모델 산출물이라 고산지대에서는 실측과 차이가 있을 수 있습니다.

## 2. 페루 빙하호 경보

| 화면 | 내용 |
|---|---|
| 요약 지표 | 가장 위험한 빙하호, 지금 녹고 있는 지점 수, 지난 7일 녹은 시간, 최근 30일 지진 |
| 위성 지도 | 실제 위성 영상 위에 12개 지점 표시. 하얀 빙하와 청록색 빙하호가 눈으로 보입니다. 위성 / 지형 / 일반 배경 전환 |
| 지점 목록 | "녹는 중 · 비 예보 · 기온 상승" 같은 한 줄 요약과 녹은 시간, 위험 점수 |
| **단면도** | 정상 → 빙하 → 0 °C 경계 → 호수 → 하류 마을을 같은 높이 축에 그린 그림. 지금 어디까지 녹는지가 설명 없이 보입니다 |
| 항목별 해석 | 다섯 항목 각각에 "이 숫자가 무슨 뜻인지" 문장으로 설명 + 낮음/보통/높음 등급 |
| 자세한 그래프 | (접어둠) 14일 기온 + 7일 예보, 0 °C 경계 vs 빙하 말단, 일별 강수(비/눈), 인근 지진, 장기 온난화 추세 |

### 숫자를 그대로 두지 않았습니다

원래 화면에는 `+344 m`, `10.2 °C·일` 같은 값이 그대로 있었는데, 그 자체로는 좋은 건지 나쁜 건지 알 수 없었습니다. 그래서:

- **융해량을 시간으로** — `융해 도일 10.2 °C·일` 대신 **`지난 7일 중 74시간(44%)이 영상`**. 도일 값은 보조로 남겨 둡니다.
- **모든 지표에 한 문장** — 예: *"이 높이 아래로는 눈이 아니라 비가 내리고 얼음이 녹습니다. 지금 그 경계가 빙하 말단보다 93 m 위에 있어, 말단부가 통째로 녹는 구간에 들어가 있습니다."*
- **점수를 만든 이유** — *"지금 점수를 끌어올린 건 주로 빙하 융해 + 강우 유입 입니다."*
- **등급의 의미** — 숫자 옆에 항상 그 등급이 무슨 상태인지 한 줄로 함께 표시.
- **결과 쪽도 사람 단위로** — *"이 호수가 터지면 물길은 23 km 아래 와라스(약 120,000명) 방향으로 흐릅니다."*

모니터링 지점은 코르디예라 블랑카(팔카코차·513·파론 등 8곳), 와이타파야나, 코르디예라 비야노타,
그리고 융해 관측용 빙하 2곳(켈카야 빙모 · 코로푸나)입니다.

## 위험도 산정 방식

다섯 요인을 각각 0~1로 정규화해 가중 합산한 뒤, 지점별 정적 취약도를 곱해 **0~100**으로 환산합니다.

| 요인 | 가중치 | 근거 |
|---|---|---|
| 빙하 융해 | 30% | 빙하 말단 고도의 지난 7일 **양의 도일(PDD)**. 융해수 유입량의 대리 지표 |
| 0 °C 동결고도 | 20% | 동결고도가 빙하 말단보다 높을수록 융해면이 넓게 노출됨 |
| 강우 유입 | 25% | 최근 3일 + 향후 3일 강우. 호수 수위를 올리고 모레인 댐을 약화시킴 |
| 급격한 온난화 | 10% | 향후 3일 평균기온 − 지난 7일 평균 |
| 지진 활동 | 15% | 반경 250 km · 30일 내 지진을 규모/거리/경과일로 감쇠. 빙벽 붕락과 댐 붕괴의 방아쇠 |

정적 취약도(`baseHazard`)는 댐 형식, 호수 용적, 하류 노출 인구, 배수 터널 등 저감 시설 유무를 반영한
0~1 값이며 `0.5 + 0.5 × baseHazard` 배율로 곱해집니다. 같은 기상 조건이라도 하류에 12만 명이 사는
팔카코차가, 배수 터널로 수위를 낮춘 파론보다 높은 점수를 받습니다.

등급은 **관심(0~24) · 주의(25~49) · 경계(50~74) · 심각(75~100)** 네 단계입니다.

### 한계

- 호수 수위 · 모레인 댐 변위 · 빙하 두께를 **직접 관측하지 않습니다.** 기상·지진이라는 외부 조건만 봅니다.
- GLOF의 상당수는 기상과 무관한 빙벽·암반 붕락으로 촉발되며, 이 모델은 그 순간을 예측하지 못합니다.
- 가중치는 문헌의 정성적 인과관계를 반영한 값이지, 관측 사례로 보정(calibration)한 값이 아닙니다.
- 지점 제원(고도·용적·인구)은 공개 문헌 기반 근삿값이며 조사 시점에 따라 편차가 있습니다.

## 실행 방법

### 1. 로컬에서 바로 보기

ES 모듈을 쓰므로 `file://` 로는 열리지 않습니다. 정적 서버가 필요합니다.

```bash
python3 -m http.server 8000
# 또는
npx http-server -p 8000
```

브라우저에서 <http://localhost:8000> 을 엽니다. 브라우저가 Open-Meteo · USGS 를 직접 호출합니다.

### 2. Synology NAS 에 상시 구동 (권장)

브라우저만 쓰면 API가 주는 **최근 며칠 창(window)** 밖에 못 봅니다.
NAS에 수집기를 띄워 두면 이력이 쌓이고, 임계값을 넘을 때 알림도 받을 수 있습니다.

**Container Manager 로 (GUI)**

1. File Station 에서 `docker/peru-glacier` 폴더를 만들고 이 저장소를 올립니다.
2. Container Manager → **프로젝트** → **생성** → 경로를 그 폴더로 지정
3. 소스를 `docker-compose.yml` 로 두고 **다음 → 완료**
4. `http://<NAS주소>:8080` 접속

**SSH 로**

```bash
git clone <이 저장소> peru-glacier && cd peru-glacier
docker compose up -d
docker compose logs -f          # 수집 로그 확인
```

첫 수집이 끝나기 전에는 `/api/latest` 가 503 을 반환합니다. 1~2분이면 채워집니다.

배포 직후 파이프라인만 먼저 검증하고 싶다면 `DEMO=1` 로 한 번 띄워 보세요.
합성 데이터로 수집 → 이력 적재 → 알림까지 전 구간이 도는지 확인할 수 있습니다.
**확인이 끝나면 반드시 지우세요.** DEMO 모드의 수치는 실제 관측값이 아닙니다.

### 환경 변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` / `HOST` | `8080` / `0.0.0.0` | 수신 주소 |
| `DATA_DIR` | `./data` | `latest.json` 과 `history/*.jsonl` 이 쌓이는 경로 |
| `POLL_MINUTES` | `30` | 수집 주기 |
| `ALERT_WEBHOOK` | (없음) | 위험도 임계값 초과 시 POST 할 URL. Synology Chat · Slack · Discord · ntfy 호환 |
| `ALERT_THRESHOLD` | `50` | 알림 임계 점수. 지점당 6시간 쿨다운 |
| `CLIMATE_REFRESH_DAYS` | `7` | 전 지구 연대별 기후를 다시 계산하는 주기(일) |
| `DEMO` | (없음) | `1` 이면 합성 데이터 사용 (배포 점검 전용) |

### API

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/latest` | 마지막 수집 묶음 (전 지점 원시 기상 + 지진) |
| `GET /api/history?site=<id>&days=<n>` | 지점별 위험도 이력 (JSONL 을 파싱해 반환) |
| `GET /api/climate` | 전 지구 19개 지역의 연대별 기후 요약 (약 90 KB) |
| `GET /api/health` | 상태 · 마지막 수집 시각 · 경과 분 |
| `POST /api/collect` | 즉시 수집 트리거 |

대시보드는 같은 오리진에 `/api/latest` 가 있으면 **자동으로** 그쪽을 씁니다.
없으면 브라우저가 직접 API를 호출하고, 그것마저 실패하면 데모 모드로 내려가되
상단에 경고 배너를 띄웁니다. 세 경우 모두 화면 우상단 배지에 현재 데이터 출처가 표시됩니다.

**npm 설치가 필요 없습니다.** 차트와 단면도는 직접 그렸고, Leaflet 은 저장소에 담아
두어 CDN 없이 로드됩니다. 외부에서 받아오는 것은 지도 타일뿐이며, 타일이 막혀도
배경만 비고 마커·수치·단면도는 그대로 동작합니다.

위험도 판정은 `assets/js/risk.js`, 연대별 집계는 `assets/js/globalclimate.js` 한 곳에만 있고
브라우저와 수집기가 이를 그대로 임포트하므로 두 경로의 결과가 어긋나지 않습니다.

### 전 지구 자료는 왜 무거운가

지역당 1950년 이후 일별 기온 약 27,000개, 19개 지역이면 원자료가 8 MB에 이릅니다.
브라우저에서 직접 열면 처음 한 번은 시간이 걸리고, 계산된 요약만 `localStorage` 에 저장해
다음부터는 즉시 열립니다(30일 보관).

**NAS 수집기를 쓰면 이 부담이 사라집니다.** 수집기가 7일에 한 번 계산해 두고
`/api/climate` 로 약 90 KB 요약만 내보내므로, 브라우저는 원자료를 아예 받지 않습니다.

### 지도에 대해

구글 지도는 API 키와 결제 계정 등록이 필요해, 키 없이 쓸 수 있는 소스를 씁니다.
기본 배경은 **위성 영상**입니다 — 빙하와 빙하호를 눈으로 직접 확인할 수 있어
이 용도에는 일반 지도보다 낫습니다. 우측 상단에서 지형·일반 지도로 바꿀 수 있습니다.

페이지를 스크롤할 때 커서가 지도 위에 있어도 지도가 확대되지 않습니다
(확대는 `Ctrl`/`⌘` + 휠, 또는 좌측 상단 버튼). 지도를 엉뚱한 곳으로 끌고 갔다면
좌측 상단 `⌂` 버튼으로 되돌릴 수 있습니다.

마커 이름표는 충분히 확대했을 때만 켜집니다. 코르디예라 블랑카는 8곳이 반경 40 km 안에
몰려 있어(팔카코차·야카·툴파라후는 서로 1~5 km) 축소 상태에서는 이름표가 겹치기
때문입니다. 그 구간에서는 마커에 마우스를 올리거나 오른쪽 목록에서 찾으면 됩니다.
